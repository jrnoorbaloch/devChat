Configuration

Most bots need no configuration beyond the messenger choice that npm run setup saves for you.

devchat.config.json

Created by npm run setup in your project folder:

{
  "messengers": ["wechat", "whatsapp"]
}

startDevChat() reads it and starts one bot per messenger. Edit it by hand or rerun npm run setup. If you add WhatsApp by hand, run npm run setup -- --yes once so its driver gets installed.

In code

// several messengers, shared logic
await startDevChat({ messengers: ['whatsapp'], setup: bot => { /* ... */ } })

// one bot, full control
const bot = DevChatBuilder.build({ name: 'support-bot', puppet: 'whatsapp' })
await bot.start()

puppet accepts the friendly names wechat and whatsapp, or the package name of any compatible driver.

Environment variables

VariablePurpose
DEVCHAT_MESSENGERSMessengers for setup/start, e.g. both, whatsapp
DEVCHAT_PUPPETDriver for DevChatBuilder.build() without a puppet option (wechat or whatsapp)
DEVCHAT_NAMEBot name. Also names the login session file, so restarts skip the QR scan
DEVCHAT_LOGLog level: silly, verbose, info (default), warn, error
DEVCHAT_DEBUGShow full technical error details
DEVCHAT_TOKENToken for a remote puppet service
DEVCHAT_PUPPET_SERVICE_TOKEN, DEVCHAT_PUPPET_SERVICE_ENDPOINTConnect to a remote puppet service
DEVCHAT_PORTHTTP port (PORT takes priority)
PUPPETEER_EXECUTABLE_PATHWhatsApp only: use an installed Chrome instead of the downloaded one

Read settings in your own code with envSetting('NAME').

Login sessions

After the first QR scan, devChat stores the session in <bot-name>.memory-card.json, for example devchat-whatsapp.memory-card.json. Keep this file private, because it can log in as your bot. Delete it to log out for good.

Docker

docker build -t devchat .
docker run -it --rm -e DEVCHAT_MESSENGERS=wechat -v "$PWD":/bot devchat bot.ts

Inside containers, run setup without questions: npm run setup -- --messenger wechat --yes.
